# rvedgedet: a homebrew RISC-V computer with a Sobel edge-detection accelerator

A small system-on-chip on the Cyclone V GX Starter Kit (`5CGXFC5C6F27C7N`), written in VHDL: a [NEORV32](https://github.com/stnolting/neorv32) RISC-V core, a UART bootloader, and a 20x4 HD44780 character LCD driven like a serial terminal. The goal is a circuit design project that measures how much faster a hardware Sobel edge detector is than the same algorithm in C on the soft core, and how each iteration of the accelerator improves on the last.

The plan, in order:

1. Run the Sobel filter in C on the CPU and measure it (cycles per pixel, frames per second).
2. Build a hardware accelerator and verify it against a Python golden model with cocotb and pyuvm.
3. Iterate on the accelerator (window reuse, line buffers, pipelining, parallel lanes) and measure each version.

## Architecture

Current system:

```
                 50 MHz
 KEY0 (reset) ──────────────┐
                            v
 USB-UART <──uart0──>  ┌──────────┐ gpio_o[7:0] ──> LEDG[7:0]
 (bootloader, debug)   │ NEORV32  │
                       │ rv32imc  │ uart1_tx ──> lcd_terminal ──> HD44780 20x4
                       │ 32k IMEM │               (uart_rx → lcd_term → lcd_driver)
                       │ 16k DMEM │
                       └──────────┘
```

Planned: the accelerator is started and polled by the CPU (start/finish) and reads and writes the frame buffers through memory (see the roadmap).

NEORV32 configuration (`rtl/top.vhd`): 50 MHz, `rv32imc_zicsr_zifencei`, 32 KiB IMEM and 16 KiB DMEM, GPIO (8 bits), CLINT, UART0 (bootloader and console) and UART1 (LCD, 64-entry TX FIFO), boot mode 0 (UART bootloader).

## Getting started

```sh
git clone --recurse-submodules <repo-url>
cd rvedgedet
make venv                      # python environment for the scripts
make                           # synthesize, fit, assemble (a few minutes)
make prog                      # program the FPGA over JTAG
```

Press **KEY0** (reset) after programming: the CPU needs a reset pulse, and the bootloader starts. The green LED 0 blinks as the bootloader's status LED.

```sh
make upload APP=blink          # build sw/blink and send it to the bootloader
make upload APP=lcd_demo       # LCD demo
```

If your toolchain has another prefix, pass it through: `make sw RISCV_PREFIX=riscv64-unknown-elf-`.

For a console: `picocom -b 19200 /dev/ttyUSB0` talks to the bootloader. Close the terminal before running `make upload`, since both use the same port.

## Makefile reference

| Target         | What it does                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------------ |
| `make`         | Generates `quartus/files.tcl`, then runs the Quartus flow: `quartus/output_files/<PROJ>.sof`      |
| `make prog`    | Programs the FPGA over JTAG                                                                      |
| `make sw`      | Builds `sw/$(APP)` with the NEORV32 makefile                                                     |
| `make upload`  | Builds, aborts the bootloader's auto-boot countdown, uploads `neorv32_exe.bin` over UART         |
| `make sim`     | Simulates `tb/$(TB).vhd` with `$(SIM)`                                                           |
| `make venv`    | Creates `.venv` and installs `requirements.txt`                                                  |
| `make golden`  | Runs `scripts/sobel.py`                                                                          |
| `make clean`   | Removes Quartus, simulation and generated files; `distclean` also cleans the app                  |

| Variable        | Default           | Meaning                                                               |
| --------------- | ----------------- | --------------------------------------------------------------------- |
| `PROJ`          | `rvedgedet`       | Quartus project / revision name                                       |
| `APP`           | `blink`           | Application in `sw/`                                                  |
| `UART_TTY`      | `/dev/ttyUSB0`    | Serial port for `upload`                                              |
| `SIM`           | `ghdl`            | `ghdl` or `questa`                                                    |
| `TB`            | `tb`              | Testbench entity and file name (`tb/$(TB).vhd`)                       |
| `ACCEL_SRC`     | `rtl/accel/*.vhd` | Sources compiled for simulation (override on the command line)        |
| `WAVES`         | `0`               | `1` writes waveforms (`.ghw` for GHDL, `.wlf` for Questa)             |
| `GUI`           | `0`               | `1` opens the Questa GUI                                              |
| `WITH_NEORV32`  | `0`               | `1` also compiles NEORV32 into library `neorv32` for simulation       |
| `CABLE`, `POS`  | auto              | JTAG cable name and chain position for `make prog`                    |
| `PY`            | `.venv/bin/python`| Python used by `make golden`                                          |

How the Quartus flow is set up: `quartus/rvedgedet.qsf` is static. It sources `files.tcl`, which the Makefile generates from NEORV32's own file list (`ext/neorv32/rtl/file_list_core.f`, compiled into library `neorv32`) plus every `rtl/*.vhd` and `rtl/*/*.vhd`. New VHDL files are picked up automatically.

## Hardware

### Pins

Taken from a community pin list for the Cyclone V GX Starter Kit; double-check against the board manual if something looks off.

| Signal                | Pin(s)                                                  | Standard      |
| --------------------- | ------------------------------------------------------- | ------------- |
| `clk` (50 MHz)        | `R20`                                                   | 3.3-V LVTTL   |
| `rstn` (KEY0)         | `P11`                                                   | 1.2-V         |
| `led[7:0]` (LEDG)     | `L7 K6 D8 E9 A5 B6 H8 H9`                               | 2.5-V         |
| `ledr[1:0]` (LEDR)    | `F7 F6`                                                 | 2.5-V         |
| `uart_rx`, `uart_tx`  | `M9`, `L9` (named from the FPGA's point of view)        | 2.5-V         |
| `lcd_rs, rw, e`       | `D26 E26 K26`                                           | 3.3-V LVTTL   |
| `lcd_d[7:4]`          | `T22 P20 M21 M26` (D7 down to D4)                       | 3.3-V LVTTL   |

The LCD is used in 4-bit write-only mode (RW is held low), so a 5 V module never drives into the FPGA.

### Indicators

- **LEDG[7:0]**: NEORV32 `gpio_o[7:0]` (the bootloader blinks LEDG0).
- **LEDR0**: LCD initialization finished.
- **LEDR1**: UART1 framing error seen (sticky): usually a baud rate mismatch between `lcd.h` and the `baud` generic in `rtl/top.vhd`.

### Memory sizes must agree

`IMEM_SIZE` and `DMEM_SIZE` in `rtl/top.vhd` have to match the `--defsym __neorv32_rom_size / __neorv32_ram_size` lines in each app's Makefile, otherwise the linker script and the hardware disagree. Both must be powers of two.

## LCD terminal

`uart1 → uart_rx → lcd_term → lcd_driver → HD44780`. Bytes go into a 20x4 character buffer, and a refresher keeps the display in sync with it, so bursts and scrolls never overflow anything: the display just catches up a few milliseconds later. Intermediate screens that were overwritten before the LCD got to them are never drawn.

| Input                       | Effect                                                                  |
| --------------------------- | ----------------------------------------------------------------------- |
| printable (`0x20-0x7e`, `0xa0-0xff`) | Written at the cursor; wrapping at column 20 is deferred until the next printable character |
| `\n`                        | Column 0 of the next row; scrolls up at the bottom                      |
| `\r`                        | Column 0 of the same row (`\r\n` is one newline)                        |
| `\f`                        | Clear screen and home                                                   |
| `\b`, `DEL`                 | Step left and erase                                                     |
| `ESC [ H`, `ESC [ r ; c H`  | Cursor to row `r`, column `c` (1-based, clamped); `f` works too         |
| `ESC [ n A/B/C/D`           | Cursor up / down / right / left by `n`                                  |
| `ESC [ n J`                 | Erase: 0 cursor to end of screen, 1 start to cursor, 2 whole screen     |
| `ESC [ n K`                 | Erase: 0 cursor to end of row, 1 start of row to cursor, 2 whole row   |
| `ESC [ ? 25 h` / `l`        | Hardware cursor (underline) on / off                                    |
| `ESC [ ? 12 h` / `l`        | Blinking block on / off                                                 |

`J` and `K` do not move the cursor. Unknown escape sequences are swallowed.

From C (`sw/lib/lcd.h`, add `APP_INC += -I ../lib` to the app Makefile). Rows and columns are 0-based there:

```c
#include <lcd.h>

lcd_init();                       // sets up UART1 at LCD_BAUD and clears the screen
lcd_print_at(0, 0, "hello");
lcd_goto(2, 0);
lcd_printf("count: %u", n);       // neorv32_uart_printf has no width/precision support
lcd_clear_eol();
lcd_cursor(true);                 // underline cursor
lcd_blink(true);                  // blinking block
lcd_clear();                      // clear + home
```

`LCD_BAUD` in `lcd.h` and the `baud` generic in `rtl/top.vhd` must be the same (115200 by default).

## Sobel golden model

The reference definition that the C code, the accelerator and the testbenches all have to match bit for bit:

- Input and output: 8-bit grayscale, 352x288 by default, row-major.
- Kernels: `gx` = (right column - left column) with weights 1 2 1, `gy` = (bottom row - top row) with weights 1 2 1.
- Arithmetic in **int32** (uint8 arithmetic wraps and gives wrong results).
- Magnitude: `min(255, |gx| + |gy|)`. No square root.
- Borders: **edge replication** (`np.pad(..., mode="edge")`), output has the same size as the input.
- Checksum: `zlib.crc32` over the raw pixel bytes (no pgm header), written as `%08x`.

Python environment:

```sh
make venv                  # or: python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
make golden                # scripts/sobel.py: writes data/golden/** and data/golden.csv
```

`data/golden.csv` has two columns, `file,crc32`, where `file` is the golden output image relative to `data/` (for example `golden/synth/checker_8_352x288.pgm`).

Some reference values for the synthetic patterns at 352x288 (noise seed 1):

| Pattern                      | Output crc32 |
| ---------------------------- | ------------ |
| `flat_0`, `flat_128`, `flat_255` | `706f5008` (all zero) |
| `step_v`                     | `9cb46874`   |
| `step_h`                     | `3e16e5d7`   |
| `impulse`                    | `024f94c4`   |
| `checker_1`                  | `56869afa`   |
| `checker_8`                  | `56ee59e2`   |

Check the input crc that the pattern generator prints before comparing outputs: the noise patterns depend on the numpy random stream.

## Simulation

```sh
make sim                                   # ghdl, tb/tb.vhd against rtl/accel/*.vhd
make sim SIM=questa WAVES=1                # questa, with waveforms
make sim TB=tb_lcd_terminal ACCEL_SRC="rtl/lcd/uart_rx.vhd rtl/lcd/lcd_driver.vhd rtl/lcd/lcd_term.vhd rtl/lcd/lcd_terminal.vhd"
```

- Build products go to `build/ghdl` and `build/questa`.
- Questa compiles files in the order given. List sources in dependency order in `rtl/accel/files.f` (one path per line, `#` comments allowed), or pass `ACCEL_SRC` as above. Without the file, `*_pkg.vhd` come first, then the rest alphabetically.
- End testbenches with `std.env.finish;` so they stop on both simulators.
- `tb_lcd_terminal` uses a strict HD44780 model with datasheet timing checks, directed tests for every feature, and random byte streams compared against an independent reference terminal.

## Software notes

- **Several source files in an app:** the NEORV32 makefile compiles every `*.c`, `*.cpp` and `*.S` in the app folder. For files from elsewhere, set the whole list before the `include` line (`APP_SRC += ...` alone drops your own sources):

  ```make
  APP_INC += -I ../lib
  APP_SRC  = $(wildcard ./*.c) $(wildcard ./*.cpp) $(wildcard ./*.S) ../lib/extra.c
  ```

- **C++** compiles, and global constructors run. Add `CXXFLAGS += -fno-exceptions -fno-rtti -fno-threadsafe-statics -fno-use-cxa-atexit -Wno-register`. libstdc++ is not linked, so `new`/`delete`, `std::string`, containers and exceptions fail at link time.
- **Debugging over UART0:** call `neorv32_uart0_setup(baud, 0)` and use `neorv32_uart0_printf`; `neorv32_rte_setup()` makes unhandled traps print a message. Keep printing out of timed regions.
- **The bootloader runs at 19200 baud.** Applications can reconfigure UART0 to a faster rate (1,000,000 baud is exact at 50 MHz).

## Troubleshooting

| Symptom                                       | Check                                                                                                   |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Nothing happens after `make prog`             | Press KEY0: the CPU needs a reset pulse after configuration                                             |
| `Invalid bootloader response` on upload       | Press KEY0 and run `make upload` straight away; make sure no terminal has the port open                 |
| No serial output at all                       | Wrong port (`UART_TTY`), no permission on the device, or `uart_rx`/`uart_tx` swapped                    |
| LCD blank, LEDR0 on                           | Contrast potentiometer, backlight, wiring                                                               |
| LEDR1 on                                      | Baud mismatch between `lcd.h` and the `baud` generic in `rtl/top.vhd`                                   |
| Quartus cannot find NEORV32 entities          | Run `make clean`, then `make`: regenerates `quartus/files.tcl`                                          |
| `make prog` cannot find the cable             | udev rule for the USB-Blaster; `jtagconfig`; `make prog CABLE=...`                                      |
| `riscv-none-elf-gcc: not found`               | Install the toolchain, or `make sw RISCV_PREFIX=<your-prefix>-` (it needs rv32 newlib)                  |
